# 台灣智慧氣象與預報準確度分析 MVP

## Problem Statement

使用者需要在同一介面查看台灣測站最新觀測、天氣圖層、警特報與最近地震，並了解鄉鎮溫度預報與後續實測相差多少。課程作業必須展示網站擷取、氣象 API、資料整理、資料庫與前端的完整流程。

## Solution

提供具原創版面的 React 地圖與分析視圖。Flask 統一取得中央氣象署資料、擷取公開特報網頁、正規化並保存到資料庫，再以自身 API 對 React 提供資料。本機使用 SQLite；Vercel 正式環境使用 Turso，保留跨部署的歷史紀錄。

## User Stories

1. 作為訪客，我能在台灣地圖查看測站位置與最新氣溫，並看到觀測時間。
2. 作為訪客，我能切換雨量、濕度、風速風向與天氣現象圖層，點擊測站查看數值、單位與缺值狀態。
3. 作為訪客，我能開關雷達透明圖層、颱風路徑、縣市邊界、深色／街道底圖與數字標籤。
4. 作為訪客，我能定位到自己的位置；未授權定位時，地圖仍可使用。
5. 作為訪客，我能查看中央氣象署公開網頁的有效天氣特報、影響地區、來源與擷取時間；擷取失敗時不會被誤導為無特報。
6. 作為訪客，我能查看最近顯著有感地震的震央、時間、規模與深度；無資料時看見空狀態。
7. 作為訪客，我能以縣市與鄉鎮市區查詢未來預報，知道不同欄位的預報時間或時段及發布時間。
8. 作為訪客，我能在有合適代表測站的行政區查看溫度預報、實測、絕對誤差與 MAE，並知道樣本數；無代表測站時只顯示預報。
9. 作為訪客，我能看見資料的新鮮度、缺值與資料來源，避免將過期或缺值資料當成即時資訊。
10. 作為維護者，我能以受保護的手動同步取得資料，得到新增／重複／失敗統計；Hobby 方案每天有一次受保護的同步。

## Implementation Decisions

- React + Leaflet 前端、Flask 後端。React 只讀 Flask API，不持有氣象署授權碼。
- 地圖觀測使用 O-A0003-001（10 分鐘）；分析使用 O-A0001-001（逐時）。F-D0047-093 提供鄉鎮預報；顯著有感地震用 E-A0015-001。雷達先採 O-A0058-005 透明影像；颱風用 W-C0034-005，在沒有活動颱風時呈現空狀態。每個額外資料集的實際回傳格式須先驗證。
- 特報擷取中央氣象署公開網頁；若網頁以 JavaScript 另外載入資料，須記錄實際網站資料流，僅取公開內容且保留來源網址。不得用 API 結果假冒網站爬蟲。
- 預報版本以發布時間、取得時間、行政區、目標時間／時段及元素識別；相同版本與目標不重複寫入，不同版本不覆蓋。觀測以測站與觀測時間去重。
- 分析只用逐時與逐 3 小時的溫度時間點，不以 12 小時平均溫度比單點觀測。逐時觀測取最近、時間差不超過 30 分鐘的有效溫度，距離相同時取較早一筆。總覽 MAE 每個行政區、目標時間只採事前最後一版預報。
- 行政區與代表測站明確配對，不自動指派遠距測站。
- 本機 SQLite，Vercel 使用 Turso；資料存取封裝於單一 repository 介面。更新端點須使用伺服器端密鑰及節流，防止公眾濫用。
- Vercel Hobby 每日排程一次，另提供手動更新。地圖稱為「最新觀測」並顯示真實觀測時間。
- 視覺設計參考截圖的資訊層級，但版面、配色與圖示採原創設計。

## Testing Decisions

以 Flask API 測試用戶可見的完整資料流（固定官方格式樣本 → 正規化 → 資料庫 → API），另測版本去重、缺值、時間配對及無代表站狀態。前端至少驗證建置和主要互動；不為純版面微調撰寫鏡像測試。

## Out of Scope

帳號、推播、AI／機器學習、全台完美測站配對、複雜 GIS、降雨或風速準確度分析、Redis、Celery、Docker、Mapbox。

## Further Notes

部署須有氣象署授權碼、Turso 連線資訊與 Vercel 帳戶；機密資訊不進 Git。Vercel MCP 可協助部署，但若此工作環境沒有可用的 MCP，改用官方 Vercel CLI。正式上線前驗證實際 API 與公開網頁擷取結果。
